# CEMS 表单字段级业务分析建议

> [下载 PDF 版（9 页，7 张关键证据图已内嵌）](/10-form-field-analysis.pdf)

> 范围：`http://cems.dev.mooke.cc/` 原站，170 个页面逐页打开"新增/新建/添加"弹窗
> 方法：真机 Chromium（经服务器 SOCKS 隧道）实测。每个弹窗记录：字段标签 / 控件类型 / 是否必填 / 占位提示；校验探针=清空首个必填文本框后失焦，看错误提示是否出现（全程不点保存、不提交任何数据）；每个弹窗截图留证。
> 数据：`forms-deep.jsonl`（170 行）、截图 `shots/forms-deep/`（93 张）
> 时间：2026-10-18

## 总览

- 170 页中 **93 个页面有新增类表单弹窗**，字段总数约 750+，平均每表单 8 字段
- 校验探针：65 个通过（首个必填为文本输入框的**全部通过**）；28 个"未通过"**全部是探针方法局限**——首个必填项为下拉/日期/上传/照片，失焦不触发这类控件的校验，不能据此下"无校验"结论
- 控件使用总体合格：金额类基本用了 number 框、日期用了日期选择器、省市区/组织上级用了级联选择；问题集中在**该用下拉选档案的地方用了自由文本**、**该自动带出/只读的地方用了手填**

## 分域分析

### 1. 合同管理（1 表单）

**新增合同**（12 字段/5 必填，`shots/forms-deep/contract_list.png`，探针通过"请输入或生成合同编号"）

| 维度 | 发现 |
|---|---|
| 业务流缺口 | **合同金额非必填**。合同台账没有金额是必失真——09 报告指出的"合同金额在项目与合同模块对不上"，根因之一就在这里：源头允许空金额入库 |
| 业务流缺口 | 签订日期非必填；开始/到期日期非必填——合同到期提醒（09 评为相对最完整的域）的数据源头就有缺口 |
| 组件误用 | 甲方/乙方是自由文本输入框。应为下拉选择（客户档案/供应商档案），否则"XX公司""XX 公司""xx公司"三种写法，统计和关联全乱 |
| 好的 | 关联项目下拉（联动中标结果）、合同编号支持自动生成、顶部有 OCR 识别合同扫描件（提示"自动识别金额/日期/签约方，采用后需人工核对"） |

### 2. 财务管理（9 表单）

**新增发票**（10 字段/3 必填，探针通过）——**最高风险**：
- 金额、税额**非必填**。结合已知的发票 OCR 返回固定假数据（09 P0），等于假发票可以零金额直接入库。发票号码占位提示"OCR 识别发票号码"，但 OCR 本身是 mock
- 对方单位自由文本 → 应下拉（往来单位档案）

**新增回款**（13 字段/6 必填，探针通过）：
- 合同金额、累计回款是**手填数字框** → 应从关联合同自动带出并只读。手填=回款进度可随意编
- 逾期是**手动开关** → 应由"到期日 vs 今天"自动计算。手动拨的逾期状态不可信
- 好的：关联合同/项目/客户必填，本次收款必填

**新增银行流水**（11 字段/5 必填）：
- 匹配项目、匹配合同是**文本输入框**（占位"自动匹配或人工指定"）→ 应为下拉选择。自动匹配没做、人工指定又不给下拉，等于没法规范关联
- 账户名称文本输入 → 应下拉（银行账户档案）；账户余额手填 → 应自动

**新增支出/收入**：金额必填 ✓、项目/费用科目下拉 ✓；支出日期非必填（支出没有日期，现金流时间维度失真）

### 3. 材料管理（9 表单）

**新增采购订单**（9 字段/5 必填，探针通过）——断环重灾区：
- 材料名称**自由文本** → 应下拉选择材料档案。自由文本的采购订单与库存里的材料永远对不上，09 说的"材料台账"数据可信度问题源头在此
- 单位自由文本（"如 吨/方/根"）→ 应随材料档案自动带出
- 单价非必填、无"金额=数量×单价"自动计算
- 关联采购计划**非必填** → 计划-订单断环，做了采购计划也白做

**新增入库**（13 字段/5 必填）：关联采购订单**非必填** → 订单-入库断环；材料名称又是自由文本；金额手填（应=数量×单价自动）；供应商下拉 ✓、仓库下拉 ✓ 是对的

### 4. 劳务分包（5 表单）——实名制红线

**新增工人**（花名册，10 字段/5 必填，探针通过"请输入姓名"）：
- **没有银行卡号字段**。实名制五联（身份/合同/考勤/工资/岗位）要求工资代发到本人银行卡，花名册连卡号都不采集，工资代发链条起不来
- 联系电话、日工资**非必填**；身份证号是文本框（占位"18位身份证号"），未见格式校验
- 好的：所属队伍/工种下拉

**新增工资单**（7 字段/3 必填，探针通过"请选择月份"）：
- 项目是**文本输入框** → 应下拉
- **应发工资、实发工资非必填** ← 工资单没有金额，可提交空单
- 无考勤天数、无银行代发流水号字段；制单人手填 → 应自动取当前用户

### 5. 招投标管理（7 表单）

**新增招标信息**（13 字段/4 必填，探针通过）：项目区域自由文本（占位"如：河南省开封市"）→ 应为省市区级联；招标单位自由文本；原文链接文本框无 URL 格式校验；预算金额非必填。来源网站/原文链接字段说明有外部抓取痕迹（1054 条外部数据，09 已指出内外混同）

**新增投标登记**：所需证书用 textarea ✓ 合适；投标金额非必填
**新增中标记录**：结果用 radio（中标/未中标）✓ 合适

### 6. 工程项目（8 表单）

**新增预算项**（项目预算，5 字段/2 必填）：**已发生金额是可编辑的数字框** → 应为只读自动汇总。允许手填"已发生"，预算执行率可随意编，09 指出的"三算对比缺失"在表单层就有体现

**新增预算**（成本管理，4 字段/2 必填）：**预算金额非必填** ← 预算单没有金额

**新增变更签证单**（10 字段/4 必填）：变更金额必填 ✓、附件上传 ✓；提出方自由文本（"发起单位/部门/人员"）→ 可接受，但最好下拉

### 7. 证件资质（10 表单）——相对最完整

抽查**新增建造师**（15 字段/10 必填，`shots/forms-deep/cert_constructor.png`）：
- 好的：顶部 OCR 识别上传、持证人照片上传组件、姓名下拉（"选择员工或输入姓名"，联动员工档案）、注册单位默认"本公司"、有效期至必填（到期提醒的数据源，09 评为最完整的域是有道理的）
- 可优化：押证费/押证状态字段是业务特色，保留

### 8. 人资管理（10 表单）

**新建员工**（17 字段/**仅 2 必填**）：手机号、身份证号、银行卡号**全部非必填、无格式校验**。PII 裸奔（09 P0）且数据质量无保障；好的：现住地址用省市区级联 ✓、所属组织/岗位/直属上级下拉 ✓

**新建薪资核算**（17 字段/**0 必填**）← **全站最离谱**：员工、薪资月份都不必填，可提交完全空白的薪资单；应发合计/实发合计是手填框 → 应=各明细自动求和只读

### 9. 组织权限（8 表单）

**新增用户**（7 字段/2 必填）：电话、邮箱非必填；角色单选下拉（是否需多选看业务，暂不判）
**新增组织**（部门，8 字段）：上级组织用级联 ✓、排序号用数字框 ✓ —— 组件用得对的正面例子

### 10. 用印管理（2 表单）

**新增用印申请**（12 字段/3 必填，探针通过）：申请人**手填** → 应自动取当前登录用户；申请日期手选 → 应默认今天；用印事由是**单行输入框** → 应为 textarea（事由通常超过一行）；授权时长数字框无条件显示（与授权模式联动未知）

### 11. 行政综合（6 表单）

**新增资产**（固定资产，13 字段/**仅 1 必填**）：分类是**文本输入框** → 应下拉（资产分类字典）；保管人文本框（占位"选择员工或手动输入姓名"）→ 应为员工下拉，"或手动输入"就是数据失真的口子；备注是单行输入框 → 应为 textarea；资产编号"二维码内容，留空自动"——有二维码规划，方向对

### 12. 设备/消息/知识库/协同（其余）

- **新增设备**（10 字段/3 必填）：购置价数字框 ✓；缺折旧/净值字段（固定资产视角不完整）
- **新增模板**（消息，6 字段/4 必填）：变量说明占位 `{certName},{expireDate}`，与证件到期提醒联动，设计是通的
- 其余表单（任务看板、日程、知识文档等）字段与组件基本合理，无硬伤

## 跨域共性问题（按严重排序）

1. **金额字段非必填**：合同金额、发票金额/税额、投标金额、预算金额、工资单应发/实发、薪资核算全单 —— 6 处。财务/合同模块的数据可信度问题，源头在表单层
2. **该下拉选档案的用了自由文本**：甲方乙方、材料名称（订单/入库两处）、项目区域、资产分类、保管人、银行流水匹配项目/合同、账户名称、工资单项目 —— 9 处。自由文本=主数据永远对不上
3. **该自动计算/只读的手填**：回款累计/逾期、入库金额、预算已发生金额、薪资合计、银行余额 —— 5 处
4. **该自动带出的手填**：申请人、制单人、申请日期默认值 —— 3 处
5. **单行 input 装多行文本**：用印事由、资产备注 —— 2 处
6. **业务链条字段缺失**：工人无银行卡号（实名制代发）、工资单无考勤天数/代发流水号、采购订单/入库关联非必填（计划-订单-入库断环）

## 修复优先级建议

- **P0（数据失真源头）**：合同金额、发票金额税额、预算金额、工资单金额改为必填；薪资核算至少员工+月份必填；已发生金额/累计回款/薪资合计改为只读自动
- **P1（主数据对齐）**：甲方乙方→客户/供应商下拉；材料名称→材料档案下拉（订单/入库）；资产分类→字典下拉；保管人→员工下拉；银行流水匹配→项目/合同下拉
- **P2（体验）**：申请人/制单人自动当前用户；申请日期默认今天；用印事由/资产备注改 textarea；项目区域改省市区级联；原文链接加 URL 校验；身份证/手机号加格式校验
