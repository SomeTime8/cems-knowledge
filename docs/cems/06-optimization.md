> 按优先级分短期（1–2 周可做）、中期（1–2 月）、长期（架构）。每条说明改什么、为什么、预期收益。

## 短期（1–2 周）

| # | 建议 | 改什么 | 为什么 | 收益 |
|---|------|--------|--------|------|
| S1 | 全站 HTTPS + 改默认账号 | Nginx HTTPS + HSTS，强制改默认密码，禁用演示账号 | HTTP 明文 Token + 默认账号 = 高危 | 消除 P0 安全风险 |
| S2 | PII 脱敏 | 员工列表接口掩码身份证/银行卡/手机号 | 接口未脱敏 | 合规，避免泄露 |
| S3 | 备份接真实 API | 删 Mock，接真实备份/下载/还原，验证一次恢复 | Mock 备份 = 无备份 | 数据可恢复 |
| S4 | 发票 OCR 接真实或禁用 | 接真实 OCR 或标注演示并禁用保存 | Mock OCR 会造假财务数据 | 财务数据可信 |
| S5 | 金额口径统一 + 对账 | 合同/项目金额同源，履约率公式明确，补对账页 | 金额不一致 | 报表可信 |
| S6 | 未知路径 404 | 全局异常处理区分 404/400/500 | 现在未知路径 500 | 排障更快，监控更准 |
| S7 | 字段校验 + 清洗 | 地区/建设单位字典化，必填校验，清洗历史占位数据 | 地区“林”、建设单位“乙方” | 数据质量提升 |
| S8 | 驾驶舱时间范围 | KPI 支持本月/本季/本年切换，明确统计口径 | 本月收支 0 易误解 | 看板可用 |

## 中期（1–2 月）

| # | 建议 | 改什么 | 为什么 | 收益 |
|---|------|--------|--------|------|
| M1 | 驾驶舱图表化 | 趋势图、占比图、预警红黄绿 | 现在仅表格 | 管理层一眼看懂 |
| M2 | 招标内外区分 | 外部信息库 vs 内部投标分 Tab，抓取来源/时间透明 | 1054 vs 5 易混淆 | 业务边界清晰 |
| M3 | 批量导入/导出 | 高频列表补导入/导出模板、列自定义 | 现在操作路径长 | 录入效率提升 |
| M4 | 审批与消息闭环 | 审批待办与消息中心联动，待审批/证件/合同到期统一提醒 | 现在分散 | 不漏审批 |
| M5 | 权限与审计 | PII 查看审计、金额修改审计、角色权限矩阵可视化 | 现在日志有但未突出关键操作 | 合规与追责 |
| M6 | OpenAPI + 命名规范 | 统一 REST 命名，生成 OpenAPI 文档 | 718 接口命名有例外 | 前后端协作更快 |
| M7 | 移动端适配 | 列表/表单在小屏下可用，审批/打卡优先适配 | 施工现场多用手机 | 现场可用 |
| M8 | 性能与缓存 | 列表缓存、字典缓存、分页优化 | 现在接口已快（0.09s），需保持 | 规模扩大不慢 |

## 长期（架构）

| # | 建议 | 改什么 | 为什么 | 收益 |
|---|------|--------|--------|------|
| L1 | 前后端分离 Mock 隔离 | Mock 代码单独目录，生产构建禁止 Mock，CI 检查 | Mock 曾混入生产 | 杜绝假数据上线 |
| L2 | 数据中台/对账 | 合同/项目/财务统一数据模型，定时对账任务 | 金额不一致根因 | 数据一致性 |
| L3 | 业务流程引擎 | 审批、合同、付款、变更签证统一流程引擎 | 现在各模块各自实现提交审批 | 流程可配置、可追溯 |
| L4 | 文件与附件治理 | 附件统一存储、版本、权限、水印 | 现在附件多为空数组 | 文档可管理 |
| L5 | 可观测性 | 统一日志、指标、告警（接口 500、慢查询、登录异常） | 现在 500 仅“系统繁忙” | 故障可定位 |
| L6 | 多租户/分公司隔离 | 组织/项目/数据按分公司隔离 | 现在分公司管理存在但数据隔离未验证 | 集团化可用 |
| L7 | 自动化测试 | 核心链路 E2E（项目→合同→付款→发票）+ API 契约测试 | 现在靠手动探针 | 回归不怕改坏 |

## 建议落地顺序

1. 先做 S1–S4（安全 + 备份 + OCR），这是底线。
2. 再做 S5–S8（数据口径 + 体验），让报表可信。
3. 再做 M1–M4（图表 + 招标 + 导入导出 + 审批闭环），提升可用性。
4. 最后做 L1–L3（Mock 隔离 + 数据模型 + 流程引擎），解决根因。
