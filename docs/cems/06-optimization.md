## 1. 根子（2026-10-17/18 表单级实测，知识库 10）

上面第 3 条的根子不在报表层，在表单层：**6 处关键金额字段非必填可空入库**（合同金额、发票金额/税额、预算金额、工资单应发/实发）；新建薪资核算 17 个字段 0 必填、应发/实发合计手填（应自动求和只读）；9 处应选档案的全是自由文本（甲乙方、材料名称、资产分类…主数据永远对不上）；劳务花名册缺银行卡号（实名制工资代发链起不来）；采购订单/入库"关联"字段非必填；回款"逾期"是手动开关而非按到期日自动算。修报表不修表单 = 白修。

## 2. 技术侧清单（按 P0/P1/P2）

**P0（安全与 Mock 技术债）**
- HTTPS+HSTS、全站强制改默认账号、PII 脱敏（见上表第 1 条）
- 发票 OCR：接真或禁用保存（见上表第 2 条）

**P1（稳定性与可观测性）**
- 后端间歇 502/500：加健康检查与重试/熔断，复刻站数据依赖它，页面数据会随之后端波动
- 未知路径统返 500 → 区分 404/400/500（全局异常处理），否则排障和监控全是噪音
- 可观测性为零 → 至少补：错误日志集中、关键接口耗时告警、前端异常上报

**P2（协作效率）**
- 718 接口命名不统一且无 OpenAPI 文档 → 统一 REST 命名、生成 OpenAPI（前后端协作与复刻对接都省事）
- 驾驶舱：KPI 卡片加趋势图与时间维度（本月/本季/本年切换），现在只有静态卡片易误解

## 3. 业务侧清单（最大风险 = 数据可信度）

- 合同金额口径统一 + 对账机制（见上表第 3 条）；先修表单必填与自动求和，再对历史空金额数据做清洗标注
- 审批/消息/合同到期断环 → 审批待办与消息中心联动，合同到期统一提醒（现在分散，易漏）
- 招标 1054 条外部抓取与 5 条内部投标混同 → 外部信息库 vs 内部投标分 Tab，来源/时间透明
- 招聘/劳务考勤/OA 资产等零数据模块未标注状态 → 无数据的模块明确标注"未启用/无数据"，别让用户猜
- 驾驶舱缺趋势图与时间维度（同技术侧 P2）
