## 关键结论速览（实测，2026-10-15 复测更新）

- **实现程度高**：前端 227 个 JS 分块、718 个 API 模式；198 个 GET 列表/统计接口探针全部返回 `code 200`，覆盖项目、合同、财务、招投标、证书、人事、材料、设备、劳务、用印、OA、知识库、消息、审批等。10-15 抽样 36 个核心接口复测全部 200。
- **数据量**：项目 7、合同 9、招标信息 1054（外部抓取）、员工仅 2（与 21 用户、30 角色对比偏少）、消息 2301、登录日志 657（+31）、操作日志 1038（+2）、菜单 358（+3，含按钮权限）。
- **核心链路通**：项目→预算→进度→质量→安全→成本；招投标→合同→付款/回款/发票，接口均可用。
- **P0 问题**（2026-10-15 更新）：
  - ✅ **数据备份已解决**：从前端 Mock 变为真实后端，`GET /api/system/backup/page` 返回 2 个真实 zip 备份（3.3MB，2026-10-15 当天生成）。
  - ⚠️ 发票 OCR 仍为 Mock（固定假发票数据）；HTTP 明文 + 登录页展示默认账号；员工 PII（身份证/银行卡/手机号）接口未脱敏。
- **P1 问题**：合同金额 0 与项目合同金额不一致、履约率全 0、本月收支 0；部分字段占位（地区“林”、建设单位“乙方”）；未知路径返回 500 而非 404；`/api/dashboard/summary` 返回 500（请用 `/api/cockpit/summary`）。
- **性能**：列表接口 0.08–0.11s，快。
- **2026-10-17 全量复查**：真实浏览器登录后 170 页逐页检查——0 空白页、0 控制台报错、0 API 失败、0 打不开；11 个新增弹窗表单校验全部正常。结论：原站问题不在渲染层，而在数据层与安全层（见 09）。
- **2026-10-17 业务对标**：9 大业务域逐域分析，对标泛普/新中大/Procore/ACC 与住建部实名制等行业实践；核心差距在管控预警层（三算对比、超预算预警、到期亮灯）系统性缺失；详见 `09-business-analysis.md`。
- **2026-10-18 表单字段级分析**：170 页逐页打开新增弹窗，93 个表单字段级拆解——6 处关键金额字段非必填（合同/发票/预算/工资单）、新建薪资核算 17 字段 0 必填、9 处该下拉选档案的用了自由文本、5 处该自动计算的手填；校验探针 65/93 通过；详见 `10-form-field-analysis.md`。

## 使用方式

- 需要再次分析 CEMS 时，加载 `~/workspace/skills/cems/SKILL.md`（CEMS Skill），按其中 Workflow 执行。
- 不要在知识库中写入密码、Token、身份证/银行卡/手机号等敏感明文。
- 远程服务器接入见 `07-access-method.md`，SSH 需显式指定 `-i <本地密钥路径>`。
