# 13 - 深层打磨建议的项目实施计划

> 目标：把 12《深层打磨建议》落成复刻工程（`tasks/cems-replicate/`）可执行的分阶段计划。
> 基准：前端 Vue 3.5 + Pinia + Element Plus（199 视图，`pure-admin-shell/src/views/cems/`，已部署 :5173）；后端按 BACKEND-PLAN-v2（Spring Boot 3.2 + JDK 17 + MySQL 8.0）；编码走 deepcode+Qwen（DeepSeek 余额不足，见记忆）。
> 工作量均为估算（单人+AI 结对），单位为人周；验收标准直接挂钩 10 的实测发现与 12 的法规条文。

## 0. 前提条件（阻塞项，先拍板）

BACKEND-PLAN-v2 文末 4 个待确认事项未决，Phase 1 之后的工作依赖后端选型：
1. 技术栈：Spring Boot（推荐）vs NestJS
2. 数据库：MySQL 8.0（推荐）vs PostgreSQL
3. 启动范围：Phase 0+1 先行 vs 全量开工
4. 数据库装 134.175.44.110 还是独立机器/数据盘

**建议**：先按"Spring Boot + MySQL 8.0 装本机 Phase 0+1 先行"开工，1 周交付登录可用后你再看效果拍板——不阻塞。

## Phase 0：工程准备（0.5–1 周）

- 后端脚手架（Spring Initializr：Web/JPA/Security/Validation/MySQL/SpringDoc），Flyway 基线
- 前后端契约：OpenAPI 文档（12 要求、06 M6），先出 auth/user/menu 三个模块
- 验收：后端启动、登录接口通、前端可调通

## Phase 1：合规红线（3–4 周）——12 §1.1 + §1.3

**1A 工资支付闭环（后端为主）**
- 新表：`wage_account`（专户：项目/银行/三方协议/备案日期）、`wage_sheet`（工资单：+银行流水号/考勤天数必填）、`wage_pay_item`（明细：工人/银行卡后4位/金额/代发状态）
- 规则：人工费用拨付周期≤1个月预警（53号第12条）；分包编表→本人签字→总包审核→代发状态机
- 前端：`labor/PayrollView.vue` 补字段（银行流水号、考勤天数、应发/实发改必填——10 发现"可提交空单"）；花名册补银行卡号字段+格式校验（10 发现缺失）
- 验收：工资单缺流水号保存被拦；超1个月未拨付有预警；台账导出含3年归档字段

**1B 发票合规（前后端）**
- OCR 接真：复用 `tasks/ocr-demo/` RapidOCR（已验证发票 10 行全对），替换前端 mock（P0-2）；保存前强制人工核对页
- 备注栏强制校验：建筑服务发票备注栏必须含发生地+项目名称（2016年第23号第3条），缺失不许保存
- 发票金额/税额改必填（10 发现非必填）；发票总额度月度监控（数电 2024年第22号）
- 验收：mock 假发票（460000/13%/XX建材）不再出现；备注栏缺失被拦；金额空保存被拦

## Phase 2：数据治理（3–4 周）——12 §2

- 主数据模块：材料档案/供应商/客户（含甲方乙方）/字典，统一编码规则（前缀+流水），新建走审批（主数据门禁）
- 10 的 9 处自由文本改下拉：甲方乙方→客户下拉、材料名称（订单/入库）→材料档案下拉、资产分类/保管人→字典/员工下拉、银行流水匹配→项目/合同下拉、工资单项目→项目下拉、项目区域→省市区级联
- 5 处手填改自动：回款累计/逾期（到期日算）、入库金额（数量×单价）、薪资合计（明细求和）、银行余额
- 历史清洗脚本：甲方三写法归一、地区"林"/建设单位"乙方"占位清洗（05 P1-2）
- 验收：10 的 9+5 问题逐项复测关闭；数据质量看板（重复率/缺失率）上线

## Phase 3：管控层（4 周）——12 §3.1

- 超预算事前预警：采购申请提交时比对目标成本，超阈值直接拦截（不是事后报表）；需要目标成本表（`project_target_cost`）
- 到期亮灯引擎：统一到期规则引擎（合同/证件/质保金/发票/人工费用），以用印+证件域（09 评最完整）为模板复制
- 三算对比 MVP：投标成本→目标成本→实际成本三栏对比表，量价分离（09 已有方法论）
- 验收：超预算申请被拦有提示；到期前 N 天亮灯+消息推送（接 06 M4 审批消息闭环）

## Phase 4：智能层（3–4 周）——12 §3.2

- 合同 AI 审阅：OCR 结果→Qwen 提取五项风险字段（对方主体/金额/期限/付款条件/违约条款，09 合同全周期要求）→人工确认入库
- 现场照片智能（可选）：安全检查拍照隐患识别——视 Phase 1–3 进展决定做不做
- 前提：Phase 2 完成（AI 读自由文本效果打折，12 已警示）；Qwen key 在 litellm-config.yaml
- 验收：抽 10 份历史合同，AI 提取金额/工期准确率人工抽查≥90%

## Phase 5：财务一体化（3–4 周）——12 §3.3

- 单据自动生成凭证：采购入库/工资单/发票→凭证（CMiC 式一体化），凭证可反查源单
- 项目独立核算：每项目成本/利润/现金流（接 Phase 3 三算）
- 数电发票→凭证→申报链路（接 1B）
- 验收：一张采购入库单自动生成凭证且可反查；项目利润表与合同金额口径一致（05 P1-1 关闭）
