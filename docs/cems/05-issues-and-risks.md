> 分级：P0 = 阻断/数据错/安全高危；P1 = 功能缺失/数据不一致/体验阻断；P2 = 规范/体验/可维护性。
> 所有问题均来自实测，区分“实测”与“推断”。Mock 类问题已通过源码验证，非猜测。

## P0

### P0-1 数据备份/还原/迁移为 Mock，未真备份
- **证据**：`SystemBackupView` 调 `systemSettings-DSwHArW4.js`，其导入 `mock-g-573mqL.js`，备份列表为硬编码 4 条（`cems_backup_20260820_103000.sql` 等，大小 256MB/251MB/248MB/245MB），“立即备份”仅 `setTimeout 1500ms` 后在前端数组前插一条假记录；还原/迁移同样为 Mock 数组。
- **风险**：用户以为已备份，实际磁盘无备份文件，数据丢失时无法恢复；页面文案称“每天凌晨 3 点自动备份”无后端佐证。
- **修复**：接真实备份 API（数据库 dump + 附件打包 + 存储 + 下载 + 还原校验），删除 Mock，上线前做一次恢复演练。

### P0-2 发票 OCR 为 Mock，返回固定假发票
- **证据**：`finance-Bkf4AF_M.js` 中发票 OCR 函数不调后端，`Promise.resolve` 返回固定假数据：发票号码、增值税专用发票、金额 460000、税率 13%、税额 59800、销方“XX建材集团”等。
- **风险**：用户上传发票以为已识别，实际为固定假数据，若未核对直接保存将导致财务数据错误。
- **修复**：接真实 OCR 服务（或明确标注“演示数据”并禁用保存），保存前强制人工核对。

### P0-3 HTTP 明文 + 登录页展示默认账号
- **证据**：CEMS 以 HTTP 提供，`Authorization: Bearer` Token 明文传输；登录页明确展示默认账号提示。
- **风险**：内网嗅探可截获 Token 直接冒充管理员；默认账号若未改密码即为后门。
- **修复**：全站 HTTPS（HSTS），上线前强制改默认账号密码、禁用/删除演示账号、开启密码复杂度与登录失败锁定、Token 短有效期 + 刷新机制。

### P0-4 员工 PII 接口未脱敏
- **证据**：`GET /api/employee/page` 返回完整身份证、银行卡、手机号等字段，未脱敏/掩码。
- **风险**：越权或日志泄露即导致个人信息泄露；不符合个人信息保护要求。
- **修复**：列表接口默认掩码（身份证/银行卡仅后 4 位、手机号中间 4 位），详情按权限返回完整字段并审计；日志中不记录 PII。

## P1

### P1-1 金额与履约数据不一致
- 项目合同金额 vs 合同金额不一致（示例见 04）；项目汇总金额 vs 驾驶舱合同总额不一致；履约率全 0 / 已确认收入 0；本月收支 0。
- **修复**：统一金额口径（合同金额 = 项目合同金额的来源），履约率 = 已确认收入 / 合同金额，明确统计时间范围，补数据校验与对账报表。

### P1-2 字段占位与截断
- 地区仅“林”、建设单位为“乙方”、多条记录负责人为“系统管理员”。
- **修复**：表单必填校验 + 字典（地区/建设单位从组织/字典选，不允许自由填“乙方”），历史数据清洗。

### P1-3 未知路径返回 500 而非 404
- **证据**：访问不存在的 `/api/*` 路径返回 `500 系统繁忙，请稍后再试`，而非 404；前端未使用的路径同样 500。
- **修复**：全局异常处理区分 404（未知路径）/ 400（参数错）/ 500（服务端异常），返回结构化错误码。

### P1-4 部分模块数据为 0（功能可用但未产生业务数据）
- 招聘、劳务工资/考勤、OA 资产/会议、协作任务、报表等为 0。
- **判断**：非 Bug，多为未启用/未录入；需与业务确认是否为“已上线未用”还是“流程未打通”。
- **修复**：上线前补演示数据或明确“待启用”标识，避免用户误以为功能坏了。

### P1-5 招标外部数据与内部数据混同
- 招标信息 1054 条为外部抓取，内部投标仅 5 条、中标 7 条。
- **修复**：UI 区分“外部招标信息库”与“内部投标业务”，抓取来源、抓取时间、去重规则透明化。

## P2

### P2-1 驾驶舱/看板无图表，仅表格
- 驾驶舱为 KPI 卡 + 钻取表格，经营看板为两张表格，无折线/柱状/饼图。
- **建议**：补趋势图（产值/收入/支出月趋势）、占比图（项目状态/合同类型），KPI 支持时间范围切换。

### P2-2 工作台统计初始为 `--`
- 工作台 4 个统计卡初始 `--`，需等待接口返回。
- **建议**：骨架屏 + 缓存上次数值，避免空白。

### P2-3 列表与表单体验
- 列表页统一为搜索 + 分页 + 弹窗 CRUD，功能全但操作路径长；部分页面无批量导入/导出入口（前端有 `/file/upload` 与导出接口，但非所有列表均暴露）。
- **建议**：高频列表补批量导入/导出、列自定义、保存筛选条件。

### P2-4 可维护性
- 前端 227 个分块、718 个 API 模式，API 命名有例外（如员工 `/employee/page` 而非 `/hr/employee/page`，材料 `/material/page` 而非 `/material/item/page`）。
- **建议**：统一 REST 命名规范，补 OpenAPI 文档，Mock 代码与真实代码分目录并标注 `__MOCK__`，禁止 Mock 进入生产构建。

### P2-5 日志与审计
- 登录日志 626、操作日志 1036，接口可用。
- **建议**：操作日志记录关键操作（删除、审批、金额修改、PII 查看），支持按用户/时间/模块检索与导出。

## 非问题（已验证纠正，避免误报）

- `/api/message/center/page`、`/api/backup/page` 等 500 为路径错误，真实消息接口为 `/api/message/page`，备份为 Mock（见 P0-1），非后端 Bug。
- `/api/cockpit/drill/1` 返回“未知指标: 1”为正确行为，正确用法为 `/api/cockpit/drill/projectCount`。
- `/api/project/list` 等 500 为前端未使用的路径，非功能缺失。
