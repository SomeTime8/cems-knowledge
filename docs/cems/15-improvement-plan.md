# 15 - 开源功能借鉴与开发改进计划

> 从 RuoYi、JeecgBoot、JimuReport、Flowable 四个开源项目提取 10 个经生产验证的功能模式，分 5 个阶段落地到 CEMS。2026-10-19。

## 1. 背景与目标

06 战略版指出的三个核心问题，本计划逐一对应用开源方案解决：

| CEMS 问题 | 对应功能 | 出处 |
|---|---|---|
| 安全：PII 明文、无数据权限 | 数据权限（行/列/字段三级） | RuoYi、JeecgBoot |
| 断环：审批/消息/合同到期各玩各的 | Flowable 工作流、定时任务、统一消息中心 | Flowable、RuoYi、JeecgBoot |
| 效率：199 视图手写、报表手写、驾驶舱静态 | 代码生成器、报表设计器、大屏设计器、Online 表单 | RuoYi、JimuReport、JeecgBoot |
| 架构：单租户硬扛多分公司 | 多租户隔离（预留） | 芋道（ruoyi-vue-pro） |

**原则**：不重复造轮子，能集成的不自研；P0 先行，体验随后；每阶段可独立交付验收。

## 2. 功能清单（含证据）

### F1 代码生成器
- **出处**：RuoYi-Vue3。配表→预览→生成 Entity/Mapper/Service/Controller/Vue 全套代码，支持下载 ZIP 或直写服务器目录；芋道支持单表、树表、主子表三种模板。
- **CEMS 缺口**：199 个视图全手写，新增模块重复造轮子。
- **落地**：随 08 后端引入，44 个模块的新表用生成器起步。

### F2 数据权限（行/列/字段三级）
- **出处**：RuoYi-Cloud 内建 Data scope permissions；JeecgBoot 精细到"行级、列表级、表单字段级，实现不同人看不同数据，不同人对同一个页面操作不同字段"。
- **CEMS 缺口**：有功能权限、无数据权限，分公司的人能看到全公司的工资单（06 P0）。
- **落地**：后端加 `@DataScope` 注解 + 部门/岗位/个人三档，优先套薪资、合同金额、员工档案。

### F3 BPM 工作流引擎（Flowable）
- **出处**：Flowable 基于 BPMN 2.0，可视化设计器定义节点/条件分支/多级审批，`runtimeService.startProcessInstanceByKey()` 一行代码启动流程；芋道已集成"动态表单、在线设计流程、会签/或签、多种任务分配"。
- **CEMS 缺口**：06 明确"审批/消息/合同到期断环"，现在是硬编码状态机。
- **落地**：合同审批、请假、报销、付款申请四个高频流程先接 Flowable。

### F4 零代码在线表单（Online）
- **出处**：JeecgBoot "在线配置表单"零代码能力；支持"单表、树表、一对多表单、select/radio/checkbox/textarea/date/popup 等控件"，配完同步数据库立即可用。
- **CEMS 缺口**：10 号文档 93 个表单字段问题（6 处金额非必填、17 字段 0 必填），全是手写欠的债。
- **落地**：新增类简单台账用 Online 表单，复杂表单仍手写，渐进替换。

### F5 拖拽报表设计器
- **出处**：JimuReport "像搭建积木一样在线拖拽设计"，涵盖数据报表、打印设计、图表报表，支持 28 种图表、分组交叉合计、SQL/API 双数据源。
- **CEMS 缺口**：06 点名"驾驶舱只有 KPI 卡片、缺趋势图"，报表全是开发手写死页面。
- **落地**：项目进度报表、薪资报表、材料统计先迁到 JimuReport，业务自己拖。

### F6 大屏设计器
- **出处**：JimuReport JimuBI "拖拽布局、几十种图表自由拼接"；JeecgBoot "敲敲云仪表盘/大屏设计器"；芋道"集成报表设计器、大屏设计器，通过拖拽即可生成"。
- **CEMS 缺口**：驾驶舱静态 KPI 卡片，06 要求加趋势图和时间维度。
- **落地**：驾驶舱重做为可配置大屏，管理层自己排组件。

### F7 可视化定时任务（Quartz）
- **出处**：RuoYi-Cloud "创建/编辑/删除定时任务、监控执行结果、支持 cron 表达式"，带任务日志。
- **CEMS 缺口**：合同到期提醒、证照到期、报表推送靠人记，06 写了"合同到期统一提醒（现在分散，易漏）"。
- **落地**：定时任务控制台 + 三个内置任务：合同到期前 30/7 天推送、证照到期提醒、日报表生成。

### F8 全链路操作日志审计
- **出处**：RuoYi-Cloud "Operation Logs 追踪用户操作、Login Logs、System Logs，支持多条件搜索过滤"；JeecgBoot "数据变更记录日志，可记录每次变更内容，通过版本对比查看历史变化"。
- **CEMS 缺口**：06 要求"错误日志集中、关键接口耗时告警、前端异常上报"，现在可观测性为零。
- **落地**：操作日志加"数据变更前后对比"，财务相关表强制审计。

### F9 统一消息中心
- **出处**：JeecgBoot "消息中心（支持短信、邮件、微信推送等等）" + "集成 Websocket 消息通知机制"。
- **CEMS 缺口**：审批待办、合同到期、消息通知三套各玩各的，06 点名"断环"。
- **落地**：一个消息中心收口：站内信 + WebSocket 实时推送 + 短信/企微，审批流转自动触发。

### F10 SaaS 多租户隔离（预留）
- **出处**：芋道"支持 SaaS 多租户系统，可自定义每个租户的权限，提供透明化的多租户底层封装"。
- **CEMS 缺口**：单租户，建筑集团"多分公司/项目部"天然是租户模型，现在靠数据权限硬扛。
- **落地**：08 后端设计时所有业务表预留 `tenant_id` 字段，MyBatis 拦截器透明封装；暂不启用，先预留。

## 3. 实施路线图

| 阶段 | 主题 | 功能 | 周期 | 前置依赖 | 优先级 |
|------|------|------|------|----------|--------|
| Phase 1 | P0 安全与断环 | F2 数据权限、F3 工作流、F7 定时任务 | 4 周 | 08 后端 Phase 0+1（登录可用） | P0 |
| Phase 2 | 开发效率 | F1 代码生成器 | 2 周 | 后端框架搭好 | P0 |
| Phase 3 | 数据可视化 | F5 报表设计器、F6 大屏设计器 | 3 周 | 后端有数据接口 | P1 |
| Phase 4 | 体验补齐 | F4 Online 表单、F8 日志增强、F9 消息中心 | 4 周 | F3 工作流上线 | P1 |
| Phase 5 | 架构预留 | F10 多租户字段预留 | 随 08 | 08 数据库设计阶段 | P2 |

**总周期**：约 13 周，与 08 后端开发并行穿插，不单独占整段工期。

**关键路径**：08 后端 Phase 0+1（1 周）→ Phase 1（4 周）→ Phase 4（4 周）。F1/F5/F6 可与 Phase 1 并行。

## 4. 分阶段详细任务

### Phase 1：P0 安全与断环（4 周）

**F2 数据权限（2 周）**
- [] 后端：`@DataScope` 注解 + AOP 切面，支持 `dept` / `deptAndChild` / `self` 三档
- [] 后端：部门表加 `ancestors` 祖级字段（RuoYi 模式），支撑"本部门及子部门"
- [] 后端：薪资、合同、员工档案三个模块先接入，其余模块按需加注解
- [] 前端：用户管理加"数据权限"页签，复用 RuoYi 的角色-数据权限配置界面模式
- [] 验收：分公司账号登录，只能看到本公司薪资；集团账号看全量

**F3 Flowable 工作流（2 周，与 F2 并行）**
- [] 后端：引入 `flowable-spring-boot-starter`，4 张核心表随 Flyway 初始化
- [] 后端：流程定义管理接口（部署/挂起/激活/删除）
- [] 后端：待办/已办/发起三类任务查询接口
- [] 前端：BPMN 设计器（用 `bpmn-js`，Flowable 官方 Modeler 的前端实现）
- [] 前端：审批中心页面（待办列表→表单+审批历史→通过/驳回/转交）
- [] 先迁 4 个流程：合同审批、请假、报销、付款申请
- [] 验收：发起→审批→归档全链路走通，审批历史可追溯

**F7 定时任务（1 周，与 F2/F3 并行）**
- [] 后端：Quartz + 可视化控制台（RuoYi 的 `SysJob` 表结构直接复用）
- [] 内置 3 个任务：合同到期前 30/7 天扫描、证照到期扫描、日报表生成
- [] 任务执行日志表，失败重试 3 次 + 告警
- [] 验收：控制台可启停任务，日志可查

### Phase 2：开发效率（2 周）

**F1 代码生成器**
- [] 后端：复用 RuoYi 的 `GenTable` / `GenTableColumn` 表结构 + 模板引擎（Velocity）
- [] 模板：单表、树表、主子表三套，对齐 CEMS 现有代码规范（信封 `{code,message,data}`、qs repeat 序列化）
- [] 前端：代码生成控制台（导入表→配置列→预览→生成）
- [] 验收：新建一张测试表，生成后前后端零改动跑通 CRUD

### Phase 3：数据可视化（3 周）

**F5 JimuReport（2 周）**
- [] 后端：引入 `jimureport-spring-boot-starter`（JeecgBoot 官方 starter，开箱即用）
- [] 迁移 3 张报表：项目进度报表、薪资报表、材料统计
- [] 权限：报表按角色授权，复用现有菜单权限体系
- [] 验收：业务人员可自行拖拽新增报表，无需开发介入

**F6 大屏设计器（1 周，与 F5 并行）**
- [] 用 JimuReport 的 JimuBI 模块，驾驶舱重做为可配置大屏
- [] 预置 2 套模板：集团驾驶舱（多项目总览）、项目驾驶舱（单项目穿透）
- [] 验收：管理层可自行调整大屏组件布局

### Phase 4：体验补齐（4 周）

**F9 统一消息中心（2 周，先做，被 F3 依赖触发）**
- [] 后端：消息表（站内信）+ WebSocket 推送（复用芋道的 Spring WebSocket 模式）
- [] 后端：短信/企微通道（JeecgBoot 有阿里云/腾讯云短信现成封装）
- [] 工作流事件监听：审批到达/通过/驳回自动发消息
- [] 定时任务事件：合同到期自动发消息
- [] 前端：右上角铃铛 + 消息中心页面（未读/已读/分类）
- [] 验收：审批流转全程有消息，合同到期前收到提醒

**F8 日志增强（1 周，与 F9 并行）**
- [] 操作日志加 `before` / `after` 快照字段，JeecgBoot 的"版本对比"模式
- [] 财务相关表（合同金额、薪资、付款）强制记录变更前后
- [] 前端：操作日志详情页加"变更对比"视图（diff 高亮）
- [] 验收：改一笔合同金额，日志里能看到改前改后

**F4 Online 表单（1 周）**
- [] 后端：引入 JeecgBoot 的 Online 表单引擎（或自研简化版：JSON Schema → 动态表单）
- [] 先用于 3 类简单台账：证照登记、车辆登记、资产登记
- [] 验收：零代码新增一张台账表，前端立即可用

### Phase 5：架构预留（随 08）

**F10 多租户字段预留**
- [] 08 数据库设计时，所有业务表加 `tenant_id` 字段（默认 0）
- [] MyBatis 拦截器预留租户过滤逻辑（暂不启用，用开关控制）
- [] 验收：表结构有字段，现有功能不受影响

## 5. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| Flowable 学习曲线陡 | F3 延期 | 先用 4 个简单流程练手，复杂会签/加签放二期 |
| JimuReport 与 Element Plus 样式冲突 | F5/F6 界面不统一 | 用 iframe 嵌入设计器，展示页自研，保持视觉一致 |
| 数据权限改造成本大 | F2 延期 | 先 3 个核心模块，其余按"用到再加"渐进 |
| 08 后端延期 | 全计划顺延 | Phase 1 的前置是 08 Phase 0+1（1 周），这是关键路径 |

## 6. 验收标准（汇总）

- [] 分公司账号看不到其他公司薪资（F2）
- [] 合同审批全流程线上走通，历史可查（F3）
- [] 合同到期前 30/7 天自动收到提醒（F7+F9）
- [] 新表 10 分钟生成 CRUD 前后端（F1）
- [] 业务人员可自行拖拽新增报表（F5）
- [] 驾驶舱大屏可配置，有趋势图（F6）
- [] 审批流转全程有消息通知（F9）
- [] 财务表变更可查改前改后（F8）
- [] 零代码新增台账表（F4）
- [] 所有业务表有 `tenant_id` 预留字段（F10）
