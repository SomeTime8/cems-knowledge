## 1.5 架构与工程决策（2026-10-19 增补）

> 以下为项目级决策，与功能清单同等效力，Phase 0 开工前已确定。

### A1 模块化单体架构（不做微服务）

后端采用 **Spring Boot 单体 + 按业务模块划分 package**（project / contract / finance / hr …），模块间只通过 interface 调用，不跨模块直接访问实现类。

**决策依据**：CEMS 是单团队、单台服务器、内部系统、需求仍在演进——教科书级的"该用单体"画像。行业共识："大多数应用都该从模块化单体起步"（团队 <15 人、无 k8s 运维成熟度时）；"微服务基础设施成本是单体的 10 倍"；2024–2025 趋势是回归更简单的集中式架构。模块边界即未来的服务边界，真到要拆的那天，模块化单体比大泥球好拆 10 倍。

### A2 代码生成器提前到 Phase 0

F1（代码生成器）从 Phase 1 提前到 Phase 0。437 个接口中约 60% 是标准 CRUD，生成器跑通后每个模块走"配表结构 → 生成 → 微调"，预计节省近一半后端编码时间。这是投入产出比最高的提前量。

### A3 API 契约先行

718 个接口命名现状混乱。开工第一件事：核心模块的 **OpenAPI 契约写死**，前端按契约对接 Mock、后端按契约实现，两边并行不互相等。这是三线并行（后端/前端美化/DevOps）能成立的前提。

### A4 部署方案：Docker Compose

| 层 | 方案 | 说明 |
|---|---|---|
| 应用（Spring Boot + Vue） | CVM + Docker Compose | 稳定负载，CVM 最便宜可控 |
| 无状态组件（Redis/ES/MinIO/监控） | CVM + Docker Compose | 官方镜像一行命令 |
| MySQL | **自建（默认）**；TencentDB 列为备选 | 备选理由：99.9999999% 可靠性、自动备份、任意时间点回档；按续费价约 100–200 元/月 |
| 镜像仓库 | 腾讯 TCR | CI/CD 配套，个人版免费额度够用 |
| Dify / Superset / OnlyOffice | CVM + Docker，视资源加机器 | 先跑起来再说 |

**排除项**：Kubernetes（单台服务器杀鸡用牛刀）、CloudBase 云托管（有状态服务禁区、CEMS 负载画像不匹配）。

**四步迁移**：1）装 Docker → 2）先迁无状态组件练手 → 3）再迁有状态组件（先备份再迁）→ 4）自研应用容器化接 CI。一键部署脚本从 rsync 升级为 `docker compose pull && up -d`。

### A5 渐进式替换（绞杀者模式）

不搞大爆炸式一次性切换。新后端先跑通登录 + 项目 + 合同三个核心模块，老系统继续并行，其他模块逐个迁移、逐个验收。任何时候出问题可切回老系统。"Rushing a big-bang rewrite is how projects die."

### A6 数据迁移 Phase 0 启动调研

原站数据的表结构、脏数据、金额口径不一致（06 战略已指出）是最大隐形坑。迁移脚本 Phase 0 就要开始写、提前跑、提前对账，不等到 Phase 4。

### A7 特性开关

新功能默认关闭，按部门/项目灰度放开。出问题关开关即可，不用回滚整个版本。"稳定完成"的硬保障。

### A8 每周演示

每周五 15 分钟演示本周成果，方向走偏一周就能发现。这是性价比最高的防返工机制。

### A9 P0 安全项进 Phase 0

06 战略第一条（HTTPS + PII 脱敏 + 强制改默认账号）不等到后面，Phase 0 搭环境时顺手做。越往后改成本越高。

## 2. 功能清单（含证据）

### F1 代码生成器
- **出处**：RuoYi-Vue3。配表→预览→生成 Entity/Mapper/Service/Controller/Vue 全套代码，支持下载 ZIP 或直写服务器目录；芋道支持单表、树表、主子表三种模板。
- **CEMS 缺口**：199 个视图全手写，新增模块重复造轮子。
- **落地**：随 08 后端引入，44 个模块的新表用生成器起步。

### F2 数据权限（行/列/字段三级）
- **出处**：RuoYi-Cloud 内建 Data scope permissions；JeecgBoot 精细到"行级、列表级、表单字段级，实现不同人看不同数据，不同人对同一个页面操作不同字段"。
- **CEMS 缺口**：有功能权限、无数据权限，分公司的人能看到全公司的工资单（06 P0）。
- **落地**：后端加 `@DataScope` 注解 + 部门/岗位/个人三档，优先套薪资、合同金额、员工档案。

### F3 BPM 工作流引擎（Flowable）
- **出处**：Flowable 基于 BPMN 2.0，可视化设计器定义节点/条件分支/多级审批，`runtimeService.startProcessInstanceByKey()` 一行代码启动流程；芋道已集成"动态表单、在线设计流程、会签/或签、多种任务分配"。
- **CEMS 缺口**：06 明确"审批/消息/合同到期断环"，现在是硬编码状态机。
- **落地**：合同审批、请假、报销、付款申请四个高频流程先接 Flowable。

### F4 零代码在线表单（Online）
- **出处**：JeecgBoot "在线配置表单"零代码能力；支持"单表、树表、一对多表单、select/radio/checkbox/textarea/date/popup 等控件"，配完同步数据库立即可用。
- **CEMS 缺口**：10 号文档 93 个表单字段问题（6 处金额非必填、17 字段 0 必填），全是手写欠的债。
- **落地**：新增类简单台账用 Online 表单，复杂表单仍手写，渐进替换。

### F5 拖拽报表设计器
- **出处**：JimuReport "像搭建积木一样在线拖拽设计"，涵盖数据报表、打印设计、图表报表，支持 28 种图表、分组交叉合计、SQL/API 双数据源。
- **CEMS 缺口**：06 点名"驾驶舱只有 KPI 卡片、缺趋势图"，报表全是开发手写死页面。
- **落地**：项目进度报表、薪资报表、材料统计先迁到 JimuReport，业务自己拖。

### F6 大屏设计器
- **出处**：JimuReport JimuBI "拖拽布局、几十种图表自由拼接"；JeecgBoot "敲敲云仪表盘/大屏设计器"；芋道"集成报表设计器、大屏设计器，通过拖拽即可生成"。
- **CEMS 缺口**：驾驶舱静态 KPI 卡片，06 要求加趋势图和时间维度。
- **落地**：驾驶舱重做为可配置大屏，管理层自己排组件。

### F7 可视化定时任务（Quartz）
- **出处**：RuoYi-Cloud "创建/编辑/删除定时任务、监控执行结果、支持 cron 表达式"，带任务日志。
- **CEMS 缺口**：合同到期提醒、证照到期、报表推送靠人记，06 写了"合同到期统一提醒（现在分散，易漏）"。
- **落地**：定时任务控制台 + 三个内置任务：合同到期前 30/7 天推送、证照到期提醒、日报表生成。

### F8 全链路操作日志审计
- **出处**：RuoYi-Cloud "Operation Logs 追踪用户操作、Login Logs、System Logs，支持多条件搜索过滤"；JeecgBoot "数据变更记录日志，可记录每次变更内容，通过版本对比查看历史变化"。
- **CEMS 缺口**：06 要求"错误日志集中、关键接口耗时告警、前端异常上报"，现在可观测性为零。
- **落地**：操作日志加"数据变更前后对比"，财务相关表强制审计。

### F9 统一消息中心
- **出处**：JeecgBoot "消息中心（支持短信、邮件、微信推送等等）" + "集成 Websocket 消息通知机制"。
- **CEMS 缺口**：审批待办、合同到期、消息通知三套各玩各的，06 点名"断环"。
- **落地**：一个消息中心收口：站内信 + WebSocket 实时推送 + 短信/企微，审批流转自动触发。

### F10 SaaS 多租户隔离（预留）
- **出处**：芋道"支持 SaaS 多租户系统，可自定义每个租户的权限，提供透明化的多租户底层封装"。
- **CEMS 缺口**：单租户，建筑集团"多分公司/项目部"天然是租户模型，现在靠数据权限硬扛。
- **落地**：08 后端设计时所有业务表预留 `tenant_id` 字段，MyBatis 拦截器透明封装；暂不启用，先预留。

### F11 文件在线预览（KKFileView）
- **出处**：kkFileView，Spring Boot 搭建，"基本支持主流办公文档的在线预览，如 doc/docx/xls/xlsx/ppt/pptx/pdf/txt/zip/rar/图片/视频/音频"，集成只要两行 JS 代码。
- **CEMS 缺口**：合同附件、图纸、发票都要下载才能看，手机端更没法看。
- **落地**：独立部署 kkFileView 服务（Docker 一条命令），合同/证照/图纸三个模块的附件列加"预览"按钮，预览源从 MinIO 取。

### F12 高性能 Excel 处理（EasyExcel）
- **出处**：阿里开源，"针对大型 Excel 文件优化，采用流式处理逐行读写，大大降低内存消耗"，"不会将整个文件加载到内存中"；"十万/百万级导入导出，防 OOM 是最大优势"。
- **CEMS 缺口**：劳务花名册、薪资核算都是大 Excel 导入，现在用的 POI 全量加载，大文件直接内存溢出。
- **落地**：08 后端统一换 EasyExcel，导入加监听器逐行校验、分批入库；导出用模板填充。

### F13 对象存储（MinIO）
- **出处**：MinIO，"轻量级的分布式对象存储系统，完全兼容 Amazon S3 接口，部署维护简单"；S3 协议兼容可无缝切换阿里云 OSS/腾讯云 COS，"只需改配置，无需改代码"。
- **CEMS 缺口**：附件存服务器本地磁盘，备份靠手工，扩容就得加盘。
- **落地**：08 后端文件上传统一走 MinIO（先单机 Docker，后期转分布式）；F11 的预览源、F5 的报表导出都从 MinIO 取。

### F14 单点登录 SSO（MaxKey）
- **出处**：MaxKey，"业界领先的 IAM 身份管理和认证产品，支持 OAuth 2.x/OpenID Connect、SAML 2.0、JWT、CAS、SCIM 等标准协议"，医疗/金融/政务都在用。
- **CEMS 缺口**：现在只有账密登录；集团以后上 OA、财务系统，账号体系割裂。
- **落地**：CEMS 作为 CAS/OIDC 客户端接入 MaxKey，一套账号走遍内部系统；企微/钉钉扫码登录顺手接了（MaxKey 原生支持）。

### F15 全文检索（Elasticsearch）
- **出处**：ES "基于 Lucene 构建的开源分布式搜索引擎，通过倒排索引高效存储和查询文本数据"；GitHub 用 ES 做 PB 级搜索，"13 亿文件和 1300 亿行代码"；中文用 IK 分词器。
- **CEMS 缺口**：合同、规章制度、知识库只能按标题模糊搜，搜不到正文里的条款。
- **落地**：合同全文、知识库文档、规章制度三类数据同步到 ES（Logstash 或定时任务），前端搜索框升级为"全文搜"，关键词高亮。

### F16 甘特图（Frappe Gantt / dhtmlxGantt）
- **出处**：Frappe Gantt，ERPNext 在用，"为 ERPNext 需要甘特视图而造"，轻量 SVG；dhtmlxGantt MIT 开源，"3 万+任务智能渲染"，支持拖拽排期、里程碑、依赖连线。
- **CEMS 缺口**：项目进度只有列表和报表，排期靠 Excel，延期了一眼看不出来。
- **落地**：项目详情页加"进度甘特图"页签，dhtmlxGantt 渲染（任务量大时性能好），任务拖拽改期回写后端。

### F17 IoT 设备监控（ThingsBoard）
- **出处**：ThingsBoard，开源 IoT 平台，"设备管理、数据采集、规则引擎、可视化"四件套，支持 MQTT/CoAP/HTTP，"30+ 可定制部件拖拽建仪表盘"，规则链可视化编排"温度超标就发邮件+开风扇"这类逻辑不用写代码。
- **CEMS 缺口**：设备管理只有静态台账，塔吊、升降机的运行状态、维保到期全靠人工巡检上报。
- **落地**：一期先接维保到期+年检到期规则告警（二期再接传感器实时数据），设备详情页嵌入 ThingsBoard 仪表盘。

### F18 异构数据同步（DataX）
- **出处**：阿里开源，"高效的离线数据同步工具，Framework + Plugin 架构，Reader/Writer 插件分别对应数据源的读和写"，覆盖 MySQL/Oracle/PG/Hive 等主流数据源；在阿里"单日同步数据超过 3 万亿条"。
- **CEMS 缺口**：招标模块 1054 条外部抓取数据，同步靠手工脚本，出错了没人知道。
- **落地**：外部招标数据、银行流水（如有）用 DataX 做定时同步，配 JSON 模板即可，不用写同步代码；同步状态接入 F7 的任务控制台。

### F19 轻量权限认证（Sa-Token）
- **出处**：Sa-Token，"轻量级 Java 权限认证框架，主要解决：登录认证、权限认证、单点登录、OAuth2.0、分布式 Session、微服务网关鉴权"。
- **CEMS 缺口**：现有 JWT 是手写拦截器，踢人下线、会话管理、权限注解都是散装实现。
- **落地**：08 后端评估用 Sa-Token 替换手写 JWT，注解式鉴权（`@SaCheckPermission`），自带会话管理、记住我、并发登录控制、踢人下线。

### F20 移动端（uni-app）
- **出处**：芋道（ruoyi-vue-pro）"管理后台的移动端采用 uni-app 方案，一份代码多终端适配，同时支持 APP、小程序、H5"。
- **CEMS 缺口**：只有 PC 端，工地现场的考勤、报验、巡检只能回办公室补录。
- **落地**：先做 H5 轻量版（审批待办、考勤打卡、消息中心三个高频场景），uni-app 一套代码，后期再套壳发 App/小程序。

### F21 CI/CD 自动化流水线（Jenkins / GitHub Actions）
- **出处**：Jenkins "开源自动化服务器，1800+ 插件"；GitHub Actions "GitHub 原生 CI/CD，push 即自动跑构建测试部署，无需维护服务器"。
- **CEMS 缺口**：靠 rsync 手工部署，2026-10-16 白屏事故根因就是"新旧文件混装 20 分钟"；cems-deploy.sh 写了但没进流水线。
- **落地**：GitHub 私有仓库 cems-replica 配 Actions：push → lint+typecheck+build → staging 部署 → 冒烟 → 人工确认 → 生产切换（复用 cems-deploy.sh 的 staging 切换逻辑）。

### F22 代码质量门禁（SonarQube）
- **出处**：SonarQube Quality Gate "定义一组合格条件（新增代码 Bug 为零、覆盖率 80%、重复率 <3%），不满足流水线直接失败"；Docker 一行命令启动。
- **CEMS 缺口**：199 个视图手写，代码质量靠人眼，cloneDeep 那种坑全靠事后救火。
- **落地**：进 CI 流水线，增量代码门禁（存量不阻塞），先开 Bug+漏洞两条规则。

### F23 监控告警自动化（Prometheus + Grafana）
- **出处**：两者常配对，"Prometheus 采集存储指标，Grafana 查询可视化告警"；Grafana 官方确认 Prometheus 为开源监控系统+时序数据库。
- **CEMS 缺口**：06 原话"可观测性为零"——原站 502/500 间歇，出事了都不知道。
- **落地**：Prometheus 采集 Spring Boot Actuator 指标 + Node Exporter；Grafana 大盘 + 告警规则（接口 P99 耗时、错误率、磁盘），告警推企微/邮件。

### F24 批量运维自动化（Ansible）
- **出处**：Ansible "开源自动化平台，集配置管理、应用部署、任务执行于一体，使用 SSH 通信，目标服务器无需装代理"；"批量执行命令、配置管理、应用部署"三大核心能力。
- **CEMS 缺口**：多台服务器（应用+数据库+MinIO+ES）的部署、配置更新全靠手工 SSH 一台台敲。
- **落地**：写 Playbook 管理服务器：部署应用、更新配置、重启服务一条命令；新机器加入改 Inventory 即可。

### F25 API 自动化测试（Apifox）
- **出处**：Apifox "API 文档、调试、Mock、自动化测试一体化，Postman + Swagger + Mock + JMeter 定位"，"定义好接口文档，调试、Mock、测试直接用，无需重复定义"。
- **CEMS 缺口**：718 个 API（原站）/ 437 个接口（复刻规划），无统一文档，联调靠口头，前后端经常对不上。
- **落地**：08 后端接口先在 Apifox 建文档 → 自动生成 Mock 给前端 → 测试用例沉淀为回归集 → 接入 CI 每晚自动跑。

### F26 RPA 办公自动化（影刀）
- **出处**：影刀 RPA "模拟人的鼠标点击、键盘输入、读取信息等操作，自动处理大量重复、有逻辑规则的工作"，服务"超 3 万家企业"。
- **CEMS 缺口**：发票录入、银行流水对账、报表填报这些重复劳动全靠人工；OCR 接入前全是手工录。
- **落地**：先试点 2 个场景：发票信息自动录入（OCR 结果 → 表单填充）、日报表自动生成推送（多系统取数 → Excel → 邮件）。

### F27 UI 回归测试自动化（Selenium）
- **出处**：Selenium "广泛使用的 Web 应用自动化测试工具"，WebDriver 驱动真浏览器，Grid 多浏览器并行，"可与 Jenkins 等持续集成工具集成"。
- **CEMS 缺口**：199 个页面，之前逐页复查靠人工截图看；每次发版回归全靠人点一遍。
- **落地**：核心 20 个页面（登录、项目列表、合同审批、薪资核算等）录 Selenium IDE 脚本 → Grid 并行跑 → 接入 CI 每晚回归。

### F28 数据库自动备份（XtraBackup）
- **出处**：Percona XtraBackup "开源热备工具，拷贝 InnoDB 文件不停 MySQL"，增量备份"只拷贝变更页"；"靠 cron 定时触发，凌晨低峰自动执行，无需人工干预"。
- **CEMS 缺口**：06 P0 的备份 Mock 虽已修成真备份，但仍是手工触发，无定时、无异地、无恢复演练。
- **落地**：cron 每周日全量 + 每日增量 → 备份文件同步到 MinIO（异地）→ 每月一次恢复演练 → 失败告警。

### F29 日志集中自动化（Loki / EFK）
- **出处**：可观测性实施路线图第一阶段即"Loki 或 EFK 实现日志集中收集"；ES 本身为海量日志分析而生（ELK 组合）。
- **CEMS 缺口**：06 要求"错误日志集中"，现在各服务日志散落在各台机器。
- **落地**：Loki（轻量，比 ELK 省资源）收集 Spring Boot + Nginx 日志 → Grafana 统一查 → 错误率告警；前端异常上报接口 → Loki。

### F30 性能压测自动化（JMeter）
- **出处**：Apache JMeter "开源纯 Java 应用，测性能和负载"，支持"CLI 命令行模式无头运行"，多线程并发采样。
- **CEMS 缺口**：上线前从没压测过，并发能力未知；原站就间歇 502/500，复刻后端不能重蹈。
- **落地**：08 后端每个 Phase 结束跑一轮 JMeter（登录、列表查询、审批提交三个核心场景），压测脚本入仓库，CI 定时跑，性能退化自动告警。

### F31 打印设计器（hiprint）
- **出处**：hiprint "基于 JavaScript 开发的打印插件"，"功能强大，支持拖拽配置打印、票据定位套打"。
- **CEMS 缺口**：合同、付款单、发票全靠浏览器裸打，发票套打这种精确定位需求现在做不了。
- **落地**：合同/付款单/发票模块加打印模板设计器，业务员自己拖字段排版，模板存后端可复用。

### F32 统一图标库（IconPark）
- **出处**：字节跳动开源，"2600 多个基础图标，通过单个 SVG 源文件即可切换线性、填充、双色和多色等多种主题"，Apache 2.0 免费商用。
- **CEMS 缺口**：图标东拼西凑，风格不统一，菜单图标有的线性有的填充。
- **落地**：全站图标替换为 IconPark，一套源文件，主题参数统一控制。

### F33 富文本编辑器（WangEditor）
- **出处**：wangEditor "开源 web 富文本编辑器，开箱即用，配置简单"，开源多年"已解决 5000+ Github issues"。
- **CEMS 缺口**：公告、规章制度、知识库只能纯文本，排版靠换行。
- **落地**：公告/通知/知识库编辑器升级为 WangEditor 5，图片上传走 MinIO。

### F34 暗黑模式（Element Plus 原生）
- **出处**：Element Plus "所有组件开箱即用支持暗黑模式"，只需在根元素切换 class，CSS 变量自动更新。
- **CEMS 缺口**：只有亮色主题，夜间加班、工地强光下都刺眼。
- **落地**：顶栏加主题切换按钮，偏好存 localStorage，自定义样式补 dark 变量。

### F35 图片裁剪（cropperjs）
- **出处**：cropperjs 标准流程"加载图片→初始化裁剪器→裁剪→导出"，头像上传场景成熟方案。
- **CEMS 缺口**：员工头像、身份证、资质证照上传原图直传，又大又歪。
- **落地**：头像/身份证/资质证照上传加裁剪框，统一输出正方形 300px。

### F36 大文件分片上传（vue-simple-uploader）
- **出处**：vue-simple-uploader "支持文件分块上传、断点续传、秒传、上传队列管理"，比 Element Upload 能力全得多。
- **CEMS 缺口**：图纸、视频、标书动辄几百 MB，单次上传断网就得重来。
- **落地**：图纸/大附件模块换分片上传，后端配合做分片合并接口（走 MinIO 直传更优）。

### F37 顶部加载进度条（NProgress）
- **出处**：NProgress "轻量级进度条组件，易于集成到单页应用"，路由切换时顶部细进度条，两行代码。
- **CEMS 缺口**：页面跳转时白屏干等，用户以为卡死了反复点。
- **落地**：路由守卫 `beforeEach` → `NProgress.start()`，`afterEach` → `done()`。

### F38 企业级图表主题（ECharts）
- **出处**：Apache ECharts "百度前端技术部开源，相比 highcharts、google charts 有相当竞争力，文档易找上手简单"。
- **CEMS 缺口**：驾驶舱图表用默认配色，配色土、字体小，与企业 VI 脱节。
- **落地**：定制一套 CEMS 主题（配色/字体/动效/ tooltip 样式），全站图表统一 `echarts.init(dom, 'cems')` 引用。

### F39 页面动态水印（防泄密）
- **出处**：微软 Edge 商业版 2026 年 12 月全面上线水印保护，"常驻水印显示浏览敏感内容的用户名与时间戳"，起威慑与溯源作用。
- **CEMS 缺口**：薪资、合同金额页面截屏外传无法溯源到人。
- **落地**：薪资/合同详情页加 Canvas 动态水印（姓名+工号+时间），MutationObserver 防删除。

### F40 骨架屏（el-skeleton）
- **出处**：Element Plus 内置 Skeleton 组件，加载占位比 spinner 更符合用户心理预期（感知更快）。
- **CEMS 缺口**：列表页数据回来前一片空白，用户以为没加载出来。
- **落地**：全站表格/卡片列表统一加 skeleton，封装 `AsyncTable` 组件一次搞定。

## 第五批：新赛道（F41–F50）——开新能力，单独立项

> ⚠️ 本批与前四批性质不同：前四批是"把现有系统做好"，本批是"长出新能力"。每个功能都建议单独立项评估，不适合批量排期。可行性分三档，已如实标注。

### 第一档：值得做，投入产出比高

### F41 AI 大模型集成（Dify）
- **出处**：Dify "开源的 LLM 应用开发平台，15.7 万 GitHub stars"，可视化编排+RAG+Agent 一体，Docker 一键部署。
- **CEMS 缺口**：制度文档、合同范本、招标文件全靠人翻，新人问老人，老人凭记忆。
- **落地**：先试点"制度问答助手"（RAG 接入规章制度库）；合同智能审核属高风险场景，暂缓。
- **前提**：服务器 16G+ 内存；大模型走 API 需预算、走本地需 GPU；文档质量决定 RAG 效果，乱文档先整理。

### F45 规则引擎（LiteFlow）
- **出处**：LiteFlow "轻量级强大的规则引擎框架"，"DSL 规则驱动复杂业务"，支持热更新，Spring Boot 原生集成。
- **CEMS 缺口**：审批条件、计价规则、报警阈值全硬编码，改一条要发版。
- **落地**：08 后端引入 LiteFlow，审批流转条件、费用计算规则走规则链，改规则不发版。
- **说明**："业务人员自己改规则"是夸大，EL 表达式仍需技术人员编写；真实价值是"改规则不用发版"。

### F48 PWA 离线应用
- **出处**：PWA "can work without an internet connection"，Service Worker 断网时提供缓存内容，Pinterest/Alibaba 均有成功案例。
- **CEMS 缺口**：工地现场信号差，考勤、巡检、安全日志断网就用不了。
- **落地**：考勤打卡、巡检填报、安全日志 3 个场景做 PWA，离线可填单，联网自动同步。
- **硬门槛**：PWA 强制要求 HTTPS，CEMS 当前 HTTP，必须先完成 06 战略的 HTTPS 改造。

### F49 国际化（vue-i18n）
- **出处**：vue-i18n 是 Vue 官方本地化库，"5M+ weekly downloads"，支持 40+ 语言复数规则。
- **CEMS 缺口**：只有中文，海外项目的外籍监理、分包商用不了。
- **落地**：中英双语先行；只给新模块和移动端 H5 做双语，老页面不动（199 页全改体力活太大）。

### 第二档：能做，但有明确前提

### F42 自助 BI（Apache Superset）
- **出处**：Superset "开源报表与数据可视化工具"，"高度可扩展"，Apache 基金会项目，企业级 BI 平台。
- **CEMS 缺口**：业务要个分析报表得等 IT 排期；JimuReport 是"IT 做报表"，Superset 是"业务自助分析"，定位不同。
- **落地**：Docker 部署，给管理层开自助分析入口。
- **前提**：多一套 Python 技术栈要人维护；"自助"的真相是 IT 建数据集、业务拖字段，不是完全自助。

### F43 在线协同编辑（OnlyOffice）
- **出处**：OnlyOffice AGPL 开源，"实时共同编辑，他人光标和改动实时可见"，支持审阅批注，OOXML 兼容度高。
- **CEMS 缺口**：投标文件、施工方案多人改靠传文件，版本混乱；KKFileView 只是"预览"，这是"协同编辑"。
- **落地**：先只做"协同编辑"一个场景，别贪多。
- **前提**：① AGPL 协议，改代码对外服务需开源，法务先过一眼；② 文档转换吃 CPU，服务器配置要够。

### F50 用户行为埋点（ClkLog）
- **出处**：ClkLog "开源可控的用户行为数据采集与分析系统"，"私有化部署+源码交付"，支持 Web/App/小程序统一采集。
- **CEMS 缺口**：199 个页面哪些没人用、哪个按钮没人点，全靠猜。
- **落地**：埋点看板指导功能裁剪和优化；只统计功能级热度，不追踪到个人。
- **前提**：员工行为监控涉及个人信息保护，上线前需明确告知和制度，HR/法务先确认。

### 第三档：建议慎重或暂缓

### F47 电子签章 ⚠️法律风险
- **出处**：行业实践"电子签章的合同无需打印盖章，经办人直接在 OA 查询最终签章版本"。
- **CEMS 缺口**：合同审批完还要打印盖章寄回，线上流程断环。
- **落地**：**内部审批用自建签章（流程留痕）；对外合同必须接持牌 CA（e签宝/法大大），自建签章无法律效力。**
- **⚠️ 法律红线**：《电子签名法》要求可靠电子签名需经 CA 认证，自己搭的签章在合同纠纷时不受法律保护。**绝不能用自建签章签对外合同。**

### F44 企业 IM（Rocket.Chat）
- **出处**：Rocket.Chat "1200 万人使用的开源通信平台"，MIT 协议，可自托管。
- **CEMS 缺口**：项目沟通靠微信群，文件散落、人员离职带不走。
- **落地建议**：暂缓。最大成本不是服务器，是**改变用户习惯**——让全公司从微信迁到 Rocket.Chat 失败率极高。除非公司层面下决心做"去微信化"，否则建了也是没人用的系统。

### F46 自建视频会议（Jitsi Meet）
- **出处**：Jitsi "最受欢迎的开源视频会议平台"，"免费、无用户数上限"，WebRTC 免安装。
- **CEMS 缺口**：项目例会、远程验收靠腾讯会议，会议纪要无沉淀。
- **落地建议**：暂缓。除非有数据合规硬性要求，否则**自建视频会议 ROI 不如直接买 SaaS**——带宽、TURN 穿透、录制存储都是持续投入。

## 5. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| Flowable 学习曲线陡 | F3 延期 | 先用 4 个简单流程练手，复杂会签/加签放二期 |
| JimuReport 与 Element Plus 样式冲突 | F5/F6 界面不统一 | 用 iframe 嵌入设计器，展示页自研，保持视觉一致 |
| 数据权限改造成本大 | F2 延期 | 先 3 个核心模块，其余按"用到再加"渐进 |
| ES 资源占用高 | F15 增加服务器成本 | 先单节点 + 3 类数据，二期再扩；数据量小可先用 MySQL 全文索引过渡 |
| kkFileView 中文乱码 | F11 预览体验差 | Linux 部署时装中文字体（Noto Sans CJK），见 kkFileView 官方文档 |
| 08 后端延期 | 全计划顺延 | Phase 1 的前置是 08 Phase 0+1（1 周），这是关键路径 |
| Selenium 脚本脆弱 | 页面一改就挂 | 用 data-testid 定位，不用 xpath；失败截图快速定位 |
| 压测打挂生产 | 影响业务 | 压测只在 staging 跑，生产压测需凌晨+限流 |
| 监控告警风暴 | 半夜被吵醒 | 告警分级（P0 电话/P1 IM/P2 邮件），收敛规则去重 |
| 暗黑模式样式遗漏 | 某些页面白底残留 | 用 CSS 变量全覆盖，上线前逐页截图对比 |
| 水印影响可读性 | 透明度太高遮挡内容 | 水印透明度 0.08–0.12，敏感页才开 |
| 自建电子签章无法律效力 | 合同纠纷不受保护 | ⚠️ 对外合同必须走持牌 CA，自建只用于内部流程留痕 |
| OnlyOffice AGPL 合规 | 改代码对外服务需开源 | 法务先确认合规边界再部署 |
| Dify 问答不准误导业务 | RAG 幻觉给出错误制度解读 | 试点期人工复核，准确率达标再推广；高风险场景（合同审核）暂缓 |
| 埋点侵犯员工隐私 | 违反个人信息保护法 | 只统计功能级热度不追踪个人，上线前明确告知+制度 |
